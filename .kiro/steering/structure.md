# Project Structure

## Directory Layout

```
indieops-ai/
├── src/                          # Source code
│   ├── _app/                     # Application-wide configuration
│   │   ├── auth.ts              # JWT verification and authorization
│   │   └── cors.ts              # CORS configuration
│   ├── api-gateway/             # Public API service
│   │   ├── index.ts
│   │   ├── index.test.ts
│   │   └── raindrop.gen.ts
│   ├── biz-brain/               # Core AI advisory service
│   │   ├── index.ts
│   │   ├── index.test.ts
│   │   └── raindrop.gen.ts
│   ├── daily-brief/             # Scheduled daily report task
│   │   ├── index.ts
│   │   ├── index.test.ts
│   │   └── raindrop.gen.ts
│   └── notification-handler/    # Queue observer for notifications
│       ├── index.ts
│       ├── index.test.ts
│       └── raindrop.gen.ts
├── db/                          # Database migrations (if used)
│   └── <db_name>/
│       └── NNNN_description.sql
├── dist/                        # Compiled output (generated)
├── .raindrop/                   # Raindrop configuration
│   └── config.json
├── .kiro/                       # Kiro IDE configuration
│   └── steering/                # AI assistant steering rules
├── raindrop.manifest            # Application resource definitions
├── package.json                 # Dependencies and scripts
└── tsconfig.json               # TypeScript configuration
```

## Module Organization

Each module (service/actor/observer/task) follows this pattern:
- `index.ts`: Main handler implementation
- `index.test.ts`: Unit tests
- `raindrop.gen.ts`: Auto-generated types (do not edit manually)

## Application Configuration (`src/_app/`)

Global configuration that applies to all handlers:
- **auth.ts**: JWT verification and authorization logic
- **cors.ts**: Cross-Origin Resource Sharing settings

These files affect all HTTP services unless overridden per-handler.

## Handler Types

- **Services**: HTTP endpoints (e.g., `api-gateway`, `biz-brain`)
- **Observers**: Event-driven processors (e.g., `notification-handler`)
- **Tasks**: Scheduled operations (e.g., `daily-brief`)
- **Actors**: Stateful background processors (none currently)

## Generated Files

- `raindrop.gen.ts`: Auto-generated by `raindrop build generate` after manifest changes
- `dist/`: TypeScript compilation output
- Never edit generated files manually

## Manifest-Driven Architecture

The `raindrop.manifest` file defines all resources:
- Services, actors, observers, tasks
- Queues, buckets, databases, caches
- Environment variables and bindings
- Visibility and domain configuration

Changes to the manifest require running `raindrop build generate` to update types.
