## Module Organization

Each Raindrop module (service, actor, observer, task) follows this pattern:

```
src/<module-name>/
├── index.ts           # Main handler implementation
├── index.test.ts      # Unit tests
└── raindrop.gen.ts    # Auto-generated types (DO NOT EDIT)
```

## Handler Types

### Services (HTTP)
- Extend `Service<Env>` class
- Implement `fetch(request: Request): Promise<Response>`
- Use Hono for routing and middleware
- Example: `api-gateway`, `biz-brain`

### Observers (Queue/Event)
- Extend `Each<Body, Env>` class
- Implement `process(message: Message<Body>): Promise<void>`
- Process queue messages or bucket events
- Example: `notification-handler`

### Tasks (Scheduled)
- Extend `Task<Env>` class
- Implement `handle(event: Event): Promise<void>`
- Triggered by cron schedule
- Example: `daily-brief`

### Actors (Stateful)
- Extend `Actor<Env>` class
- Implement `fetch()` for HTTP and `alarm()` for scheduled work
- Maintain durable state across invocations
- Not currently used in this project

## Generated Files

**raindrop.gen.ts** - Auto-generated by `raindrop build generate`:
- Type-safe `Env` interface with all resource bindings
- Updated whenever `raindrop.manifest` changes
- Never edit manually

## App-Level Configuration

**src/_app/** - Shared configuration for all modules:
- `auth.ts` - Authentication and authorization hooks
- `cors.ts` - CORS policy for HTTP services

These apply globally unless overridden at the module level.

## Naming Conventions

- **Manifest resources**: kebab-case (e.g., `api-gateway`, `agent_memory`)
- **Environment bindings**: UPPER_SNAKE_CASE (e.g., `env.API_GATEWAY`, `env.AGENT_MEMORY`)
- **Directory names**: kebab-case matching manifest names
- **TypeScript**: camelCase for variables, PascalCase for types/classes

## Resource Access Pattern

```typescript
// In services (Hono context)
const smartbucket = c.env.DOCUMENTS;
const queue = c.env.NOTIFICATIONS;

// In actors/observers/tasks (class context)
const smartbucket = this.env.DOCUMENTS;
const memory = this.env.AGENT_MEMORY;
```

## Testing

- Tests colocated with implementation (`*.test.ts`)
- Run with Vitest: `npm test` or `npm run test:watch`
- Test files mirror the structure of implementation files
